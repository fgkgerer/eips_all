# ERC-721: Non-Fungible Token Standard（非同质化代币标准）

## 基本信息

| 属性       | 值                                                            |
| ---------- | ------------------------------------------------------------- |
| 编号       | EIP-721 / ERC-721                                             |
| 标题       | Non-Fungible Token Standard                                   |
| 状态       | Final                                                         |
| 类型       | Standards Track                                               |
| 分类       | ERC                                                           |
| 作者       | William Entriken, Dieter Shirley, Jacob Evans, Nastassia Sachs |
| 创建日期   | 2018-01-24                                                    |
| 依赖标准   | ERC-165（强制）                                                |
| 被依赖标准 | ERC-1155（参考）, ERC-8004, ERC-2981                          |

## 概述

ERC-721 是以太坊上**非同质化代币（NFT）**的标准接口。每个 token 都有一个唯一的 `tokenId`，不可分割，独立追踪所有权。与 ERC-20 的"同质化"（1 个代币 = 任何其他 1 个代币）不同，ERC-721 的每个 token 都是独一无二的——就像数字房产证。

## 核心动机

在 ERC-721 之前，链上资产只能以同质化形式存在（ERC-20）。但许多数字资产天然不同质：

- **数字艺术品**：每件作品价值不同
- **虚拟地产**：每个地块位置和价值不同
- **游戏装备**：每件装备属性不同
- **域名**：每个域名独一无二
- **身份凭证**：每个人的身份不可互换

ERC-721 为这些场景提供了标准的所有权追踪和转移接口，使得 NFT 可以跨钱包、跨市场互操作。

## 技术规范

### 接口定义

```solidity
// EIP-721: Non-Fungible Token Standard
interface IERC721 is IERC165 {
    // ========== 所有权查询 ==========
    function balanceOf(address owner) external view returns (uint256 balance);
    function ownerOf(uint256 tokenId) external view returns (address owner);

    // ========== 转账 ==========
    function safeTransferFrom(address from, address to, uint256 tokenId) external;
    function safeTransferFrom(address from, address to, uint256 tokenId, bytes calldata data) external;
    function transferFrom(address from, address to, uint256 tokenId) external;

    // ========== 授权 ==========
    function approve(address to, uint256 tokenId) external;
    function getApproved(uint256 tokenId) external view returns (address operator);
    function setApprovalForAll(address operator, bool approved) external;
    function isApprovedForAll(address owner, address operator) external view returns (bool);

    // ========== 事件 ==========
    event Transfer(address indexed from, address indexed to, uint256 indexed tokenId);
    event Approval(address indexed owner, address indexed approved, uint256 indexed tokenId);
    event ApprovalForAll(address indexed owner, address indexed operator, bool approved);
}

// ========== 可选扩展：元数据 ==========
interface IERC721Metadata {
    function name() external view returns (string memory);
    function symbol() external view returns (string memory);
    function tokenURI(uint256 tokenId) external view returns (string memory);
}

// ========== 可选扩展：枚举 ==========
interface IERC721Enumerable {
    function totalSupply() external view returns (uint256);
    function tokenByIndex(uint256 index) external view returns (uint256);
    function tokenOfOwnerByIndex(address owner, uint256 index) external view returns (uint256 tokenId);
}
```

### 核心机制

#### 所有权模型

```
mapping(uint256 => address) private _owners;      // tokenId → owner
mapping(address => uint256) private _balances;    // owner → token 数量
mapping(uint256 => address) private _tokenApprovals; // tokenId → 单个授权者
mapping(address => mapping(address => bool)) private _operatorApprovals; // owner → operator → 是否全部授权
```

与 ERC-20 不同，ERC-721 没有"额度"概念——授权是"是/否"的二值状态：

- `approve(to, tokenId)`：授权某个地址转移**指定的** token
- `setApprovalForAll(operator, true)`：授权某个地址转移**所有的** token（如 OpenSea 市场合约）

#### `safeTransferFrom` vs `transferFrom`

这是 ERC-721 的重要安全机制：

| 方法 | 行为 |
| ---- | ---- |
| `transferFrom` | 直接转移，不检查接收方 |
| `safeTransferFrom` | 转移后检查接收方是否支持 ERC-721（通过 ERC-165 检测） |

```solidity
function safeTransferFrom(address from, address to, uint256 tokenId) public {
    transferFrom(from, to, tokenId);
    require(
        _checkOnERC721Received(from, to, tokenId, ""),
        "ERC721: transfer to non-ERC721Receiver implementer"
    );
}

// 接收方需实现的接口
interface IERC721Receiver {
    function onERC721Received(
        address operator,
        address from,
        uint256 tokenId,
        bytes calldata data
    ) external returns (bytes4);
}
```

如果 `to` 是合约地址且没有实现 `IERC721Receiver`，`safeTransferFrom` 会 revert——防止 token 被永久锁死在无法处理 NFT 的合约中。

#### Token URI 与元数据

`tokenURI(uint256 tokenId)` 返回一个 JSON 文件的 URI，该文件描述 token 的元数据：

```json
{
  "name": "CryptoKitty #42",
  "description": "一只可爱的小猫",
  "image": "ipfs://Qm.../kitty42.png",
  "attributes": [
    { "trait_type": "毛色", "value": "橘色" },
    { "trait_type": "稀有度", "value": "传奇" }
  ]
}
```

常见的 URI 方案：`ipfs://`（去中心化存储）、`https://`（中心化服务器）、`data:application/json;base64,`（完全链上）。

## 应用领域

### 在 DEX（Uniswap）中的应用

Uniswap V3 的**流动性仓位（Position）**是 ERC-721 token：

```solidity
// Uniswap V3 流动性仓位 = ERC-721 NFT
contract UniswapV3Pool {
    // 每个流动性提供者的仓位是独一无二的：
    // - 价格范围不同
    // - 费用等级不同
    // - 存入金额不同
}
```

用户提供流动性时，mint 一个代表该仓位的 NFT；移除流动性时 burn 该 NFT。NFT 可以转让、抵押，甚至作为其他 DeFi 协议的抵押品。

### 在 NFT（OpenSea）中的应用

OpenSea 等 NFT 市场完全建立在 ERC-721 之上：

- **交易**：`safeTransferFrom` 是 NFT 交易的核心执行操作
- **挂单**：卖家通过 `setApprovalForAll` 授权市场合约转移 token
- **元数据展示**：市场读取 `tokenURI` 显示图片和属性
- **懒铸造（Lazy Minting）**：卖家对 token 元数据 + 价格签名，买家铸造时提交签名

```solidity
// OpenSea 挂单流程
// 1. 卖家: setApprovalForAll(opensea, true)
// 2. 卖家: EIP-712 签名挂单数据
// 3. 买家: 调用 market.executeOrder(order, signature)
// 4. 市场合约: token.safeTransferFrom(seller, buyer, tokenId)
```

## 与其他标准的关系

| 相关标准    | 关系类型   | 说明                                                    |
| ----------- | ---------- | ------------------------------------------------------- |
| **ERC-165**  | 强制依赖   | ERC-721 必须实现 `supportsInterface`，interfaceID = `0x80ac58cd` |
| **ERC-2981** | 配合使用   | NFT 版税信息通过 ERC-2981 的 `royaltyInfo` 查询         |
| **ERC-1155** | 竞争/互补  | 更高效的多代币方案，但 ERC-721 仍是唯一性资产的标准      |
| **ERC-8004** | 被依赖     | AI Agent 身份以 ERC-721 NFT 形式注册                    |

## 安全考虑

### 1. 转账到合约地址

始终使用 `safeTransferFrom` 而非 `transferFrom`，防止 token 永久锁死在合约中。

### 2. `approve` 与 `setApprovalForAll` 的区别

`setApprovalForAll(operator, true)` 给予 operator **完全控制权**——可以转移所有 token。撤销授权时别忘了设回 `false`。

### 3. 重入风险

`safeTransferFrom` 会调用接收方的 `onERC721Received`，如果接收方是恶意合约，可能触发重入攻击。ERC-721 实现应遵循 Checks-Effects-Interactions 模式。

### 4. Token ID 碰撞

跨合约时，token 的唯一标识是 `(contractAddress, tokenId)`。同一个 tokenId 在不同合约中代表不同资产。
