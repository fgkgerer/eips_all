# ERC-165: Standard Interface Detection（标准接口检测）

## 基本信息

| 属性       | 值                                                            |
| ---------- | ------------------------------------------------------------- |
| 编号       | EIP-165 / ERC-165                                             |
| 标题       | Standard Interface Detection                                  |
| 状态       | Final                                                         |
| 类型       | Standards Track                                               |
| 分类       | ERC                                                           |
| 作者       | Christian Reitwießner, Nick Johnson, Fabian Vogelsteller, Jordi Baylina, Konrad Feldmeier, William Entriken |
| 创建日期   | 2018-01-23                                                    |
| 依赖标准   | 无                                                            |
| 被依赖标准 | ERC-721, ERC-1155, ERC-2981, ERC-4626, ERC-4337 等           |

## 概述

ERC-165 定义了一套标准方法，用于**在链上查询某个合约是否支持特定接口**。它解决了一个根本问题：在调用合约之前，如何安全地确认它实现了你需要的接口，而不依赖错误回滚或猜测。

## 核心动机

在智能合约的可组合生态中，合约 A 需要调用合约 B，但不知道 B 是否实现了某个接口（例如 ERC-721 的 `safeTransferFrom`）。没有 ERC-165 时：

- 只能用 `call` 然后检查 `extcodesize` 或捕获 revert
- 无法区分"没有该函数"和"函数内部逻辑 revert"
- 不同合约的相同函数选择器可能含义完全不同

ERC-165 提供了一种**确定性的、低成本的、标准化的**接口查询方式。

## 技术规范

### 接口定义

```solidity
// EIP-165: Standard Interface Detection
interface IERC165 {
    /// @notice 查询合约是否实现了 interfaceID 指定的接口
    /// @param interfaceID 接口标识符（4 字节）
    /// @return true 表示合约实现了该接口，不应 revert
    function supportsInterface(bytes4 interfaceID) external view returns (bool);
}
```

### 核心机制

#### Interface ID 的计算方式

Interface ID 是该接口中**所有函数选择器的 XOR（异或）结果**：

```
interfaceID = selector1 XOR selector2 XOR selector3 XOR ...
```

其中 `selector = bytes4(keccak256("functionSignature"))`。

**示例：ERC-721 的 Interface ID**

```solidity
// ERC-721 必须实现的函数（不含 ERC-165 自身）：
bytes4 constant INTERFACE_ID_ERC721 =
    bytes4(keccak256("balanceOf(address)")) ^                          // 0x70a08231
    bytes4(keccak256("ownerOf(uint256)")) ^                            // 0x6352211e
    bytes4(keccak256("safeTransferFrom(address,address,uint256)")) ^    // 0x42842e0e
    bytes4(keccak256("safeTransferFrom(address,address,uint256,bytes)"))^// 0xb88d4fde
    bytes4(keccak256("transferFrom(address,address,uint256)")) ^       // 0x23b872dd
    bytes4(keccak256("approve(address,uint256)")) ^                    // 0x095ea7b3
    bytes4(keccak256("setApprovalForAll(address,bool)")) ^             // 0xa22cb465
    bytes4(keccak256("getApproved(uint256)")) ^                        // 0x081812fc
    bytes4(keccak256("isApprovedForAll(address,address)"));            // 0xe985e9c8
// = 0x80ac58cd
```

#### 实现 `supportsInterface`

```solidity
// ✅ 声明了哪些接口，supportsInterface 就宣称支持哪些，并且必须实现对应函数
contract MyContract is IERC165, IERC721, IERC721Metadata {
    function supportsInterface(bytes4 interfaceID) external view returns (bool) {
        return interfaceID == type(IERC165).interfaceId       // 0x01ffc9a7
            || interfaceID == type(IERC721).interfaceId       // 0x80ac58cd
            || interfaceID == type(IERC721Metadata).interfaceId; // 0x5b5e139f
    }

    // 必须实现 ERC-721 的所有函数
    function balanceOf(address owner) external view returns (uint256) { ... }
    function ownerOf(uint256 tokenId) external view returns (address) { ... }
    function safeTransferFrom(address from, address to, uint256 tokenId, bytes calldata data) external { ... }
    function safeTransferFrom(address from, address to, uint256 tokenId) external { ... }
    function transferFrom(address from, address to, uint256 tokenId) external { ... }
    function approve(address to, uint256 tokenId) external { ... }
    function setApprovalForAll(address operator, bool approved) external { ... }
    function getApproved(uint256 tokenId) external view returns (address) { ... }
    function isApprovedForAll(address owner, address operator) external view returns (bool) { ... }
    // ERC-721Metadata
    function name() external view returns (string memory) { ... }
    function symbol() external view returns (string memory) { ... }
    function tokenURI(uint256 tokenId) external view returns (string memory) { ... }
}
```

### 如何检测合约是否实现了 ERC-165 本身

调用 `supportsInterface`，传入 `type(IERC165).interfaceId`（值为 `0x01ffc9a7`）：

- 如果返回 `true` → 支持 ERC-165
- 如果返回 `false` 或 revert → 不支持（或支持但明确返回 false）

## 应用领域

### 在 NFT（OpenSea）中的应用

ERC-721 和 ERC-1155 **强制要求**实现 ERC-165。NFT 市场在交互前检测：

```solidity
// OpenSea 在 safeTransferFrom 前检测合约是否支持 ERC-721
function safeTransferNFT(address token, address to, uint256 tokenId) internal {
    require(
        IERC165(token).supportsInterface(0x80ac58cd),  // ERC-721
        "Token does not support ERC-721"
    );
    IERC721(token).safeTransferFrom(msg.sender, to, tokenId);
}
```

常见的检测场景：

| 检测接口             | Interface ID  | 用途                              |
| -------------------- | ------------- | --------------------------------- |
| ERC-165 自身         | `0x01ffc9a7`  | 确认合约支持接口检测              |
| ERC-721              | `0x80ac58cd`  | 确认是 NFT 合约                   |
| ERC-721Metadata      | `0x5b5e139f`  | 确认支持 `tokenURI` 等元数据查询  |
| ERC-721Enumerable    | `0x780e9d63`  | 确认支持按索引枚举 token          |
| ERC-1155             | `0xd9b67a26`  | 确认是多代币合约                  |
| ERC-2981             | `0x2a55205a`  | 确认支持版税查询                  |

## 安全考虑

### 1. 不要盲目信任 `supportsInterface` 的返回值

恶意合约可以在 `supportsInterface` 中返回 `true`，但实际上并未正确实现接口。ERC-165 是**声明式检测**，不是**行为保障**。关键操作仍需通过实际函数调用验证。

### 2. Interface ID 碰撞

理论上 4 字节的 interface ID 可能碰撞，但概率极低（约 1/2³²）。标准制定时已验证主流接口之间无碰撞。

### 3. 代理合约的 ERC-165

代理合约的 `supportsInterface` 结果取决于实现方式。如果代理通过 `fallback` 委托调用，需要显式覆写 `supportsInterface` 以正确聚合实现合约的接口信息。
